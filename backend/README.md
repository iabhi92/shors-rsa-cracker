# Backend

A FastAPI wrapper around this repository's own `rsa/`, `attacker/`, and `quantum/` packages.
Every computational endpoint calls that real code directly -- nothing here is mocked,
hardcoded, or a fabricated result. See `../WEBSITE_IMPLEMENTATION_PLAN.md` for the full
architecture and endpoint-to-source-module mapping.

## Setup

From the **repository root** (imports like `from rsa.core import ...` rely on the repo root
being on `sys.path`, which `backend/app/main.py` sets up automatically regardless of your
current directory):

```bash
python3 -m venv .venv          # if you haven't already, per the root README
source .venv/bin/activate
pip install -r backend/requirements.txt
uvicorn backend.app.main:app --reload --port 8000
```

Health check: `curl http://localhost:8000/api/health` -> `{"status":"ok"}`.
Interactive API docs (auto-generated by FastAPI): `http://localhost:8000/docs`.

## Configuration

One optional setting, `CORS_ALLOW_ORIGINS` (comma-separated), defaulting to the Vite dev
server's origin (`http://localhost:5173`). Copy `backend/.env.example` to `backend/.env`
(git-ignored) to override it locally, or set it as a real environment variable in production.

**No IBM credentials are ever read by this backend.** `IBM_QUANTUM_API_KEY` and
`IBM_QUANTUM_CRN` (used by `quantum/ibm_hardware.py` and `scripts/run_on_ibm_hardware.py`,
documented in the repo root's `.env.example`) are a completely separate, CLI-only concern --
`backend/app/routers/ibm.py` only ever reads the already-committed
`data/ibm_hardware_run_a7_N15.json` result file. There is no code path anywhere in `backend/`
that imports `qiskit_ibm_runtime` or could submit a new hardware job.

## Safety limits

Every endpoint that runs real computation caps its inputs to sizes that finish in low
single-digit seconds -- see `backend/app/limits.py` for the full list and the reasoning
behind each number (not arbitrary; several were tightened after actually measuring slow
cases during development, e.g. the gate-level Shor backend is restricted to N=15 after N=65
was measured to take minutes).

## Tests

```bash
pip install -r ../requirements-dev.txt   # ruff, mypy
pytest backend/tests -v                  # 42 tests: every endpoint, success + failure + limits + no-secret-leakage
ruff check backend/
mypy backend/
```

These run alongside (not instead of) the core project's own test suite (`pytest tests`) --
`pytest tests backend/tests` runs both.
